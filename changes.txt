The changes:

Change A. Voices
Let the user define different voice profiles and let the user select one of these in each alarm-set.
A voice profile shall consist of the following properties:
- Name (0-20 characters; default empty; unique not empty)
- TTS-Engine (default System-standard)
- Language (default System-standard)
- Voice (default System-standard)
- Speed (0.5 - 2; default 1)
- Pitch (0.5 - 2; default 1)
- Stereo-Balance Pan (-1 - 1; default 0)
- Volume (0 - 100 %; default 80 %)
The user shall define several voice profiles (assumed 5).

Remove the property audio volumne from the alarm-set (in backend and UI).
Add a property "voice profile" in the alarm-event (in backend and UI). As default take the "Standard" voice profile.
There shall be always one voice profile named "Standard" which is not editable and not deletable.

UI
The existing voice configuration screen shall be removed.
In the configuration screen have one button "voice profiles" at the top (replace the existing voice configuration button).
This button opens the voice list screen.
The voice list screen shows the list of all voice profiles.
This list (similar like the alarm-set list) lists all voice.
The list shall show the following properties: Name, speed, volumne
The list shall show buttons edit, duplicate and remove like in the alarm-set list (no remove button for the "Standard" voice profile; have "view" button for the standard profile instead of the edit button)
On click on remove, the voice profile shall be removed (After confirmation dialoge).
On click on the dupclicate button, the voice profile shall be dupclicate (with name suffix "(Kopie)")
On click on the edit button the voice profile screen shall open.
The voice profile screen shall list all properties (editable) as already right now implemented in the voice configuration screen.
The voice profile screen shall have save, duplicate and delete button at the bottom (same layout and function as in alarm-set and alarm-event screen; not for "Standard" voice profile).
In addition have one textbox "Vorschautext" (default "Es ist 7 Uhr 30. Guten Morgen.") and one "play now" button (just with a icon as in alarm-event screen.) This "play now" button plays the vorschautext with the configured voice properties above.

If the remove button is pressed (either in the voice list screen or voice profile screen), but the voice profile is still used by at least one alarm-event, ask the user in a dialoge:
"The voice profile is used in following alarm-events: <alarm-set name> <alarm-event time> <alarm-event message>. These alarm-event will get voice profile "Standard". Are you sure to delete the voice profile <voice profile name>?"
If the user still confirms update as proposed, otherwise cancel the action.

When adding/changing voice profiles, ensure unqiue names of the voice profiles. If a name is not unique, reject the save action and give a hint "name already used" in the UI.

Change H: Relative and absolute time values
In the alarm-set add a property, if the alarm-events are defined by absolute or relative time values.
If the switch is set to "absolute time values", it behaves as right now: Each alarm-set has a given time of day, when the alarm-event shall trigger.
If the switch is set to "relative time values", then the alarm-set shall have a "end time" as time of the day. The individual alarm-events then have configured a relative time offset to the "end time" of the alarm-set. E.g. "end time" in alarm-set is "8:00", the time offset is "10 min" in the alarm-event. Then it shall trigger at "7:50".

Change L: Bluetooth-device notification
Motivation: The user shall be warned, if no proper Bluetooth device is connected.

Have a property "Check for sound device" which is on or off (default off).
Have a property "Accepted devices", which is a list of paired Bluetooth devices (multiselection.)
Have a property "Warning ahead", which is a non-negative integer (1-10 min, default 2).

Change M: Keep-alive Bluetooth device and connection
Have a property "enforce Bluetooth connection", which is on or off (default off).
Have a propery "keep awake cycle" which is a non-negative integer (1-60 min, default 10 min).

If an alarm-event is planned to be triggered within the next "keep awake ahead", then play every "keep awake cycle" a 3 s silent audio sound.
